# Vehicle assets

A vehicle asset is a glTF/GLB model plus a JSON manifest. WrapForge uses the
manifest for physical dimensions, panel identity, UV bounds, validation, and
licensing. The model supplies geometry and UVs; it is not the source of truth for
panel metadata.

## Directory layout

```
assets/<asset-id>/
  manifest.json
  model/
    vehicle.glb          # required, binary glTF
    vehicle.blend        # optional source
  previews/
    thumbnail.png        # optional, used in lists
    hero.png             # optional, large preview
```

Paths inside the manifest are relative to the asset directory and must not
contain `..`, absolute components, or backslashes.

### Field rules

- `units` must be `mm`. Dimensions are physical millimetres.
- `dimensionsMm` must be positive. They are the overall vehicle envelope, not
  the bounding box of every accessory.
- `license.id` is required. `redistributionPermitted: false` is rejected for
  bundled assets.
- `panels[].id` must be stable and unique. Placement and print references use it.
- `panels[].objectName` must match the mesh object name in the glTF.
- `panels[].category` is one of `hood`, `roof`, `door`, `fender`, `quarter`,
  `bumper`, `trunk`, `other`.
- `panels[].side` is `left`, `right`, or `center`.
- `panels[].outwardAxis` is `+X`, `-X`, `+Y`, `-Y`, `+Z`, or `-Z`.
- `dimensionsMm.width/height` are the planar panel size used for print math.
- `uv.hasUv` must be true for wrap-able panels; missing UVs produce a warning and
  distorted placement.
- `uv.overlapDetected` should be false. Overlap produces a warning.
- Non-wrap surfaces (glass, lights, tyres, interior) should be separate objects
  with `wrapable: false`.

## glTF conventions

- One mesh object per panel is strongly preferred. The sample uses 13 `WF_*`
  objects.
- Each wrap-able object must have a UV layer (`TEXCOORD_0`).
- The UV layout must map the **outer face** to the unit square. Bevel and edge
  faces may collapse to a corner; they are not printed.
- The object's outer face must be planar. Curved panels cannot be printed
  correctly in this alpha.
- Export with extras so panel metadata survives:
  - `panelId`
  - `wrapable`
  - `uvWidthUnits` / `uvHeightUnits` if applicable
- Y-up export is conventional for three.js; Blender imports it back correctly.
- Avoid external texture references. The application loads the GLB from a blob
  URL, so external files will not resolve. Use embedded or no textures.
- Keep the model under 200 MB. Smaller is better; the sample is a few MB.

## Physical dimensions

`dimensionsMm.width/height` drive print size:

```
trim width  = panel.dimensionsMm.width  × scale
trim height = panel.dimensionsMm.height × scale
output      = trim + 2 × bleed
pixels      = ceil(output_mm / 25.4 × dpi)
```

If these numbers are wrong, every print is wrong. Measure the actual vehicle or
use a licensed, verified dataset. The sample dimensions are plausible, not
measured.

## Creating an asset

### Procedural sample (reproducible)

```bash
blender -b --factory-startup --python tools/generate_sample_vehicle.py -- \
  --out assets/sample-vehicle
```

With Flatpak Blender, pass absolute paths visible to the sandbox (under `$HOME`):

```bash
flatpak run org.blender.Blender -b --factory-startup \
  --python /home/you/wrapforge/tools/generate_sample_vehicle.py -- \
  --out /home/you/wrapforge/assets/sample-vehicle
```

The script builds the vehicle, assigns planar outer-face UVs, exports glTF,
saves a `.blend`, renders preview images, and writes the manifest.

### Manual asset

1. Model the vehicle with separate wrap panels.
2. UV-unwrap each outer face to the unit square.
3. Name objects consistently and set the panel ID as a custom property.
4. Export GLB with extras.
5. Create `manifest.json` with dimensions and license.
6. Render preview images.
7. Validate:

```bash
cd backend
.venv/bin/python -c "
from pathlib import Path
import json
from wrapforge_backend.models import VehicleManifest
from wrapforge_backend.asset_validation import validate_manifest
root = Path('../assets/sample-vehicle')
m = VehicleManifest.model_validate(json.loads((root/'manifest.json').read_text()))
print(validate_manifest(m, root).model_dump_json(indent=2))
"
```

## Validation

The application and backend check:

- metric units;
- license presence and redistribution permission;
- at least one wrap-able panel;
- UV availability and overlap warnings;
- model path safety and existence;
- model size limit;
- total panel area.

A validation score in the manifest is informative. It is not a substitute for
checking dimensions against a real vehicle.

## Licensing and provenance

Every asset must declare a license that permits its use. For bundled assets,
redistribution must be permitted. Do not include:

- manufacturer CAD or configurator data without a license;
- third-party logos or trademarks;
- commercial fonts;
- scans or models of unknown origin.

Record the source, attribution, and any modifications in the manifest. The
sample vehicle and artwork are CC0-1.0.

## Importing a user's own model

**Vehicle Setup → Import 3D model** accepts a `.glb` (or a self-contained
`.gltf`). The import does not need a manifest: WrapForge derives one.

| Step | What happens |
|---|---|
| Read | The file is parsed with the glTF loader. Draco/KTX2-compressed models are rejected with a message; re-export without compression. |
| Normalise | The longest bounding-box axis becomes the length, the shortest the up axis. The model is rotated so forward is +X, up +Y, left +Z, scaled to metres, centred, and dropped onto the ground plane. |
| Units | The length is matched against metres, centimetres, millimetres, inches, feet, and decimetres, picking the factor that lands nearest 4.35 m. Uncertain results are reported. |
| Front | The end whose low deck surface runs longer from the end is treated as the front (bonnets are longer than boots). |
| Panels | Each body triangle is bucketed by centroid height and position along the car, plus its facing direction. Panels carry a confidence value. |
| Texture | The first base-colour texture is extracted to `assets/vehicle/base-texture.png` and becomes the livery's starting surface. |

The model and its texture are copied into the project folder on the first save
(`assets/vehicle/model.glb`). Imports are limited to 50 MB per file (the bundled
asset pipeline allows more, because it is trusted).

### What the detection can and cannot see

- It finds doors, bonnets, boots, bumpers, fenders, and quarters on ordinary
  car-shaped models. On a real 4.3 m scanned car it named 14 panels covering
  roughly 70% of the body triangles.
- It cannot see shut lines, badges, or panel gaps. Confidence is a heuristic.
- Glass is excluded when it has its own mesh or material (name patterns
  `glass`, `window`, `light`, `tyre`, `rim`, … or a transparent material).
  A single-mesh model with a baked texture paints its glass too.
- Meshes without UV coordinates are excluded when the rest of the model has
  them, because they cannot receive the livery.

### Rendering imported models

Blender renders four things that the app cannot guess:

- **Scale** — a model that is not within a factor of two of a real car length is
  scaled to about 4.35 m before the studio stage is built, so lights, camera clip
  planes, and shadows behave the same for every import.
- **Exposure** — area-light energy follows the model radius, keeping the
  reference exposure of the bundled sample vehicle.
- **Texture orientation** — textures are written in the glTF convention (PNG row
  0 is `v = 1`). Blender stores images bottom-up, so the render script flips
  every project texture before use. Without that, livery and artwork appear
  mirrored front-to-back.
- **Livery atlas** — the composed livery texture replaces the model's base-colour
  image node; panel-based assets keep their own rendered panel textures.

### Licensing

Imported models keep their own license. WrapForge records
`license.id = "user-supplied"` and `redistributionPermitted: false`; the model is
stored inside the user's project folder and never uploaded or bundled. Check the
license of anything you import, and never publish a project containing a model
you do not have the right to redistribute.
