# Changelog

All notable changes are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses
[Semantic Versioning](https://semver.org/spec/v2.0.0.html). Pre-1.0 versions may
break compatibility.

## [Unreleased]

### Added

- Import any self-contained glTF vehicle: unit and orientation normalisation,
  front detection, ground placement, and heuristic panel detection with per-panel
  confidence. Verified on a real 4.3 m car scan (14 panels, 70% of body
  triangles classified) and on the Khronos CC0 ToyCar sample, which has no
  semantic names and had to be rescaled from 7 cm.
- Assets that are not car-sized after unit inference are rescaled to 4.35 m, so a
  toy-scale or unit-less model still gets usable panel areas and print math.
- Texture livery editing: paint and erase directly on the body texture with
  vector strokes, layer stack (stripe, rectangle, ellipse, triangle, chevron,
  text, image), blend modes, and per-layer opacity.
- Projected decal layers (`side-left`, `side-right`, `top`, `front`, `rear`)
  rasterised through the model UVs, so stripes follow body panels. Measured:
  98% of projected pixels land inside UV islands on the test model.
- Body finish modes: keep the original texture, tint it through its luminance, or
  flood a solid colour.
- Three original livery presets inspired by Japanese street tuning, containing no
  brand marks.
- Atlas export as PNG at up to 4096 px — the same texture the viewport and Blender
  use.
- Blender renders accept the composed livery texture and replace the model's base
  colour textures with it. Imported models are rescaled and re-exposed so the
  studio stage behaves the same for centimetre, inch, or millimetre assets.
- Project textures are flipped into Blender's image convention, which fixes
  front-to-back mirrored artwork and liveries in renders.
- Transparency: alpha brushwork, transparent PNG export, transparent render
  background.
- WebGL failures are reported in the viewport instead of crashing the studio.
- Studio inspector tabs (Livery, Panels, Artwork, View) with a roomier layout.
- Panel correction after import: rename a detected panel, merge it into a
  neighbour, or remove it. Panel ownership bytes and areas are rewritten, and
  every edit is a single undo step.

### Changed

- Project schema is now v2. Schema v1 projects migrate automatically and gain a
  disabled livery.
- Studio inspector widened, section spacing and control sizes increased, toolbar
  and badge spacing normalised.
- Panel areas and dimensions for imported models are computed in metres instead
  of being double-scaled.
- Panel ownership is stored as a one-byte-per-triangle map instead of thousands
  of triangle ranges: the imported test project went from 1.6 MB to 85 kB.
- Panel detection keeps bonnets and boots below the beltline, so raked
  windscreens are no longer counted as bonnet area.

### Fixed

- The studio no longer loses the model's base texture when you leave the studio
  and come back: the base-texture hook was revoking a blob URL it did not own.
- Windows narrower than ~1150 px no longer scroll horizontally. The shell grid
  could grow past the viewport because of the canvas' intrinsic size, and the
  status bar now hides secondary items instead of overflowing. Inspector tabs
  wrap instead of hiding behind a scrollbar.

## [0.1.0-alpha.0] - 2026-10-18

First public alpha. Linux only; no signed installers.

### Added

- Tauri 2 desktop shell with hardened CSP and a browser development fallback.
- Versioned project document (schema v1), Zod validation, migration from v0, and
  newer-schema rejection.
- Project create/save/load/open, atomic writes with `.bak`, recent projects,
  thumbnails, dirty tracking, undo/redo, and debounced autosave.
- Original CC0 sample vehicle generated by a checked-in Blender script: 13 wrap
  panels, planar outer-face UVs, dimensions, area, validation report, glTF and
  preview images.
- three.js viewport with PBR environment lighting, orbit/pan/zoom, panel picking,
  paint, per-panel artwork textures, isolation, edges, camera presets, and PNG
  capture.
- SVG import with sanitization, raster import, live text artwork, and CC0 sample
  SVGs.
- UV placement editing: position, width, rotation, opacity, visibility, lock,
  duplicate, delete, undo/redo.
- Print planning: units, scale, bleed, safe margin, DPI, pixel/memory estimates,
  clipping and live-text warnings, and print-ready/draft labelling.
- PNG panel export with trim, safe area, crop marks, registration marks, and
  labels; SVG panel export; JSON production manifest.
- Blender discovery (configured path, `WRAPFORGE_BLENDER`, PATH, common paths,
  Flatpak), version classification, and engine probe.
- Managed headless Blender rendering with per-panel textures, studio lighting,
  camera presets, progress events, metadata JSON, logs, and cancellation.
- Diagnostics view with environment facts, Blender self-test, and redacted
  bundle export.
- English and German localization for shell, navigation, and common actions;
  dark-first theme and a real light theme; command palette and shortcuts.
- Test suites: 53 frontend unit tests, 52 backend tests (2 Blender-marked),
  11 Rust tests, and 1 browser end-to-end workflow.
- Documentation set, issue/PR templates, CI workflows, Apache-2.0 license,
  NOTICE, and third-party notices.

### Changed

- Cycles renders are forced to CPU. Eevee reports an unknown device rather than
  claiming GPU use.
- Print exports without zero errors *and* zero warnings are labelled `draft`
  and prefixed `wrapforge-draft-`.
- Blender 5.2's `BLENDER_EEVEE` engine identifier is detected by probing instead
  of hard-coding the older `BLENDER_EEVEE_NEXT` name.

### Fixed

- Sample asset 404s in development by serving `assets/` as Vite's public
  directory.
- Blown-out first render by reducing studio light energy and world strength.
- Rust borrow-checker errors in render job handling.
- React fast-refresh warning by extracting the `cx` helper.
- three.js deprecation warning by using `PCFShadowMap`.
- Models from saved projects failing to load in the desktop app because the CSP
  `connect-src` did not allow `blob:` URLs. `blob:` and `data:` are now allowed
  for local model/texture fetches.

### Known issues

- No CMYK/ICC/spot colour, PDF/X, or TIFF output.
- No geometric unfolding; UV placement only.
- Planar, camera, and surface-conforming projection are not implemented.
- Live text is not outlined; exports warn instead.
- The sample vehicle is stylized, not manufacturer-accurate.
- Flatpak Blender can only read visible paths (home or `/tmp`).
- No automated desktop UI test for the full IPC path.
- No Windows/macOS builds, signing, notarization, or auto-update.
- German feature copy is incomplete.
